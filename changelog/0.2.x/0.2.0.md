# 0.2.0 — 2026-10-02

## Added

- **`cern_opendata_search_records` filters `category`, `keywords`, `magnet_polarity`, `stripping_stream` and `stripping_version`**, each with a live facet; `category` buckets carry `subcategories`, and `Heavy-Ion Physics` also sends its leading-space spelling, echoed under `expanded`. Keywords are sent as given, exact and case-sensitive ([#12](https://github.com/cyanheads/cern-opendata-mcp-server/issues/12)).
- **`cern_opendata_list_reference` topics `categories` and `lhcb`** — snapshots dated 2026-10-01 of the physics categories with the experiments using each, and the LHCb magnet polarities, stripping streams and stripping versions ([#12](https://github.com/cyanheads/cern-opendata-mcp-server/issues/12)).
- **Record fields `variables`, `category`, `pileup_html`, `keywords`, `magnet_polarity` and `stripping`** on `cern_opendata_get_records` and `cern-opendata://record/{recid}`, absent when the record lacks them; pile-up datasets join `links` with `source: 'pileup'` ([#13](https://github.com/cyanheads/cern-opendata-mcp-server/issues/13)).
- **`cern_opendata_get_records` `body_offset`** — with one documentation or news id, returns its body from that offset in slices of up to 30,000 UTF-16 units; a slice with more to read carries `body_next_offset`, and above 0 with several ids fails `invalid_body_offset` ([#11](https://github.com/cyanheads/cern-opendata-mcp-server/issues/11)).
- **Public hosted endpoint** `https://cern-opendata.caseyjhand.com/mcp`, listed as a `streamable-http` remote in `server.json` and documented in the README.

## Changed

- **`cern_opendata_get_records` holds each response to 64,000 bytes (breaking)** — a call may now return fewer records than it asked for: records past the budget are left out whole and listed under the new, always-present `deferred`. Pass `deferred` back as `ids` to fetch them ([#11](https://github.com/cyanheads/cern-opendata-mcp-server/issues/11)).
- **`cern_opendata_list_files` `files[].key` and `files[].https_url` are optional (breaking)** — `key` is absent for index members the portal lists without one, and `https_url` where no safe URL can be built; read `filename` when `key` is absent ([#17](https://github.com/cyanheads/cern-opendata-mcp-server/issues/17)).
- **`cern_opendata_search_trigger_paths` finds paths outside `HLT_`** (`AlCa_`, `DST_`, `DQM_`, output modules, `HLTriggerFinalPath`) by their own names, in the case given, and also with `HLT_` prepended; `effectiveQuery` now echoes the query sent, and an `_`-led path is refused ([#15](https://github.com/cyanheads/cern-opendata-mcp-server/issues/15)).
- **`cern_opendata_get_analysis_env`** names the `body_offset` where a cut guide quote stops, for `cern_opendata_get_records` to read on ([#11](https://github.com/cyanheads/cern-opendata-mcp-server/issues/11)).
- **Server instructions and tool descriptions** name prefixed recids and state trigger coverage as 2011–2016.

## Fixed

- **Prefixed recids** (`atlas-160006`, `cms-93956`) work on every recid input and the record resource, reduced to the lowercase, unpadded form the portal stores; `cern_opendata_get_records` reads them and their portal URLs as recids ([#6](https://github.com/cyanheads/cern-opendata-mcp-server/issues/6)).
- **`cern_opendata_search_records` sort direction** — `mostrecent` returns the newest `date_published` first and `title_desc` sorts Z–A; filter-only browsing now starts from the newest records ([#7](https://github.com/cyanheads/cern-opendata-mcp-server/issues/7)).
- **Malformed `query` strings** — an unbalanced parenthesis, range bracket or double quote, or a trailing `\`, fails `invalid_query` before any request; a query search whose every attempt answers HTTP 500 fails with the new `query_server_error` ([#9](https://github.com/cyanheads/cern-opendata-mcp-server/issues/9)).
- **`cern_opendata_list_files` with `index`** reads only that index unless the record's manifest is cached, so indexes of the largest records list within the call budget; a budget expiry names the portal, the 50 s budget and the next step ([#10](https://github.com/cyanheads/cern-opendata-mcp-server/issues/10)).
- **`cern_opendata_list_files` keyless index members** are listed instead of failing the record as `upstream_unreadable`, with an `https_url` on the portal's `/eos/opendata/` route; an index stating no file count or size reports them from its members ([#17](https://github.com/cyanheads/cern-opendata-mcp-server/issues/17)).
- **Trigger titles naming several datasets** — `path` drops the ` (A, B datasets)` suffix and the new `datasets` lists every name; `dataset` stays set only for a single name, and the notices mention `year` only where it applies ([#8](https://github.com/cyanheads/cern-opendata-mcp-server/issues/8)).
- **HTML-to-text keeps a bare `<`** — selection cuts such as `|eta| < 2.4` render whole in `content[]`; a `<` opens a tag only before a letter, `/`, `!` or `?` ([#14](https://github.com/cyanheads/cern-opendata-mcp-server/issues/14)).
- **`cern_opendata_get_validated_runs` on a CMS collision dataset with no list** — `no_validated_runs` names its run period and whether a published list covers it, instead of calling it non-collision data ([#16](https://github.com/cyanheads/cern-opendata-mcp-server/issues/16)).
