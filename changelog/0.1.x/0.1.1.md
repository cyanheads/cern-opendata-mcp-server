# 0.1.1 — 2026-10-01

## Added

- **`cern_opendata_search_records`** — full-text query and exact-vocabulary filters (experiment, type, collision energy and type, file type, year, event count, availability, collection) with eight live facets and an `applied_filters` echo. Paging reaches the first 10,000 matches, and the last reachable page says so ([#1](https://github.com/cyanheads/cern-opendata-mcp-server/issues/1)).
- **`cern_opendata_get_records`** — resolves 1–20 recids, DOIs, CMS dataset paths or documentation slugs per call; each record carries a `license` with its `basis` and, when it has a DOI, a `citation` that names its authors ([#3](https://github.com/cyanheads/cern-opendata-mcp-server/issues/3)). Unresolved ids return under `missing` with guidance.
- **`cern_opendata_list_files`** — a record's file indexes and files with XRootD URIs, HTTPS URLs, sizes, adler32 checksums and tape availability, 1–500 per cursor page. Umbrella records return their `children`; tape-only records report the file count their metadata states ([#2](https://github.com/cyanheads/cern-opendata-mcp-server/issues/2)).
- **`cern_opendata_get_analysis_env`** — a record's container images, CMSSW release and global tag, up to 50 linked condition, VM, validation and example-software records, and quoted sections of the first two linked guides, up to 12,000 characters each.
- **`cern_opendata_get_validated_runs`** — CMS good-run lists selected by dataset recid, list recid or run period, `full` or `muons_only`, with per-run luminosity-section ranges, up to 2,000 runs a call. A dataset recid bounds the runs to the dataset's own run range ([#4](https://github.com/cyanheads/cern-opendata-mcp-server/issues/4)).
- **`cern_opendata_search_trigger_paths`** — CMS HLT path records (2010–2016) by exact name or `HLT_…*` prefix, optionally by year, parsed into first and last run seen, per-version run ranges, L1 seeds and HLT menu links, with the source abstract alongside.
- **`cern_opendata_list_reference`** — static, offline tables for ten topics: experiments, record types, collision energies and types, file types, availability, identifier forms, query syntax, licensing and CMS run periods.
- **`cern-opendata://record/{recid}`** — one record in the `cern_opendata_get_records` shape, with a 15-minute public cache hint.
- **`CernOpenDataService`** — paces every portal request at 50 a minute (the portal allows 60 per client IP) under one 50-second deadline per call, retries included; responses have per-route byte ceilings and redirects are refused. Search always includes tape-resident (`ondemand`) records.
- **Configuration** — keyless and read-only, with no server-specific environment variables; runs over stdio or Streamable HTTP, with stateless HTTP sessions.
- **Data terms** — data and metadata are CC0 under the CERN Open Data Terms of Use; software, container images and guide code are licensed per record, and each record reports its `license.basis`. Portal text is relayed as data, fenced or escaped in `content[]`.
