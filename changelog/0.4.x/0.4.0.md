# 0.4.0 — 2026-11-21

## Added

- **Record production metadata** includes ordered methodology steps, links and configuration details in the record tool and resource. Set `include_scripts: true` on the tool to retrieve the verbatim inline scripts. ([#37](https://github.com/cyanheads/cern-opendata-mcp-server/issues/37))
- **CMS simulation cross sections** appear in the record tool and resource with the original portal values and documented units. ([#38](https://github.com/cyanheads/cern-opendata-mcp-server/issues/38))
- **`CERN_OPENDATA_CLAMP_LIMITS=false`** opts into advertised page maxima and rejects oversized limits.

## Changed

- **Page caps** rise to 1,000 for records, 625 for trigger paths, and 2,000 for file entries.
- Record and trigger searches that previously clamped the page size to 50 can now return `page_window_exceeded`. Pass `limit: 50` to keep the previous offsets. ([#34](https://github.com/cyanheads/cern-opendata-mcp-server/issues/34))
- **`cern_opendata_get_records`** returns every resolved record in the lookup batch. Only IDs past the first 20 distinct inputs are deferred. ([#35](https://github.com/cyanheads/cern-opendata-mcp-server/issues/35))

## Fixed

- **File listings** page indexes and regular files together in record scope and report counts for both. Existing cursors resume at their original regular-file offset. ([#39](https://github.com/cyanheads/cern-opendata-mcp-server/issues/39))
- **Portal search responses** can be up to 64 MiB, accommodating pages of long documentation within the existing deadline. ([#36](https://github.com/cyanheads/cern-opendata-mcp-server/issues/36))
- **Long configuration scripts** render reliably in fenced blocks.
- **Desktop bundles** retain the MCP SDK modules needed to serve skills.
- **Release and validation scripts** reject invalid command-line arguments.
- **Vitest under Bun** uses thread workers by default to support the standard test command.
